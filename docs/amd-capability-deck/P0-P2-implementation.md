# AMD Capability Deck — P0/P1/P2 Implementation Plan

This tracker records the approved implementation scope for the AMD procurement capability deck. It is intentionally documentation-only and must not modify AionSi website production code or assets.

## P0 — mandatory before external release

- Use the approved AionSi logo asset only; eliminate recreated or duplicated wordmarks.
- Replace leadership PHOTO placeholders with approved leadership photographs when assets are available.
- Remove sales-like labels such as `BEST FIT` and `now with AMD staffing evidence`.
- Use customer-neutral wording such as `CUSTOMER WORK PACKAGE / ROADMAP` unless AMD roadmap access is explicitly authorized.
- Separate management-provided corporate metrics (`30+ tapeouts`, `270+ engineers`) from workbook-specific staffing records (`24 deployed`, `60 proposed DV/PD`).
- Validate every external technical, corporate and case-study claim before release.
- Move AIV out of the main narrative unless its scope and governance wording are internally approved; retain only verified controls.
- Add an evidence/disclosure-control framework covering public, controlled and confidential evidence.

## P1 — qualification and account-conversion improvements

- Reframe the narrative around `Requirement -> Capability -> Evidence -> Bounded Pilot -> Scaled Delivery`.
- Consolidate repetitive technical slides into stronger Verification and Physical Implementation evidence slides where appropriate.
- Turn the public physical-design case study into a true case-study format: challenge, engineering scope/ownership, scale, complexity, outcome and disclosure boundary.
- Add actual technical leadership profiles with approved photos, years and domain ownership.
- Convert the capability taxonomy into concrete work-package entry points: DV, AXI/PCIe/DDR, SoC, PD, STA/signoff and related specialist areas.
- Strengthen the procurement qualification path with technical workshop, pilot, quality/supplier qualification, specialist pod and ODC progression.
- Keep all AMD language customer-neutral unless an authorized relationship/program reference is available.

## P2 — presentation quality

- Replace decorative semiconductor graphics with technical engineering diagrams.
- Improve visualization for DV skill density and PD seniority/capacity.
- Improve ODC architecture to show technical leadership, DV/PD pods, governance, continuity and scalable capacity.
- Strengthen the closing slide with a proposed next step: technical qualification workshop / bounded pilot work package.
- Keep the current 20-slide version as the working master; target a future external core + appendix structure after content validation.

## Source / safety boundary

- Current master artifact reviewed: `AIONSI_AMD_Procurement_Capability_Deck_v0_6_Semiconductor_Art_Direction.pptx`
- Do not modify website production code or assets as part of AMD deck work.
- Do not include customer-confidential technical details.
- Do not include proprietary AionSi IP where it could imply a competing product.
- The eventual deck repository must remain separate from `Aionsi-Website` when repository creation is available.
